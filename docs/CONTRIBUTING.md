# Contributing to Nekocord

Nekocord is maintained by [flufstails](https://github.com/flufstails). Contributions that add plugins, improve Discord Android compatibility, refine the UI, or expand documentation are welcome.

---

## Ways to Contribute

- **Built-in plugins:** Add new Vencord-style plugins under `runtime/src/plugins/<slug>/` with live hooks and complete `README.md` frontmatter.
- **Bug fixes and Discord version updates:** Repair broken Metro selectors, chat row transforms, or native DEX loader hooks when stock Discord Android updates.
- **Settings and theme engine improvements:** Enhance Discord-native React Native components, theme semantic token mappings, or backup/updater reliability.
- **Documentation:** Improve plugin authoring guides, troubleshooting notes, and per-plugin `README.md` docs.

---

## Repository Structure

| Path | Purpose |
| :--- | :--- |
| `runtime/src/` | TypeScript client runtime, Metro resolver, monkey-patcher, storage, themes, OTA updater, and UI modal. |
| `runtime/src/plugins/<slug>/` | Built-in plugins (`index.ts` + `README.md`). Never edit `registry.generated.ts` manually. |
| `runtime/src/plugins/_shared/` | Reusable helpers for chat row transforms, outgoing text macros, URL cleaners, and Flux interceptors. |
| `runtime/scripts/generate-plugins.mjs` | Generates `registry.generated.ts` and [PLUGINS.md](PLUGINS.md) from plugin directories. |
| `android/` | Native Android loader sources compiled into `classes4.dex` for injection into Discord. |
| `patcher/` | DEX patcher, Android binary manifest rewriter (`axml.mjs`), split APK repacker/signer (`patch.mjs`), and ADB hot-reload script (`push-dev.mjs`). |
| `docs/` | Developer guides and auto-generated plugin catalog ([PLUGINS.md](PLUGINS.md)). |
| `assets/` | Project branding assets (notably `assets/nekocord-logo.png`). |

## Prerequisites & Local Setup

1. Install required build tools:
   - **Node.js 20+** and `npm`
   - **JDK 11+** (including `javac` and `d8`)
   - **Python 3**
   - **Android SDK** (`build-tools` and `platforms`, configured via `ANDROID_HOME` or `ANDROID_SDK_ROOT`)
   - **apktool.jar** (located via `APKTOOL_JAR` or `~/apktool/apktool.jar`)
2. Place unmodified stock Discord Android split APKs inside `apk/`.
3. Install Node dependencies:

```sh
npm install
```

## Development Workflow

Always run generation and typechecking before building bundles or APKs:

```sh
# 1. Regenerate plugin registry & docs/PLUGINS.md and run tsc --noEmit
npm run typecheck

# 2. Bundle runtime (nekocord.js + nekocord-preload.js) into dist/runtime/
npm run build:runtime

# 3. Push updated JS bundles directly over ADB for rapid testing
npm run push:dev -- --serial <device-serial>

# 4. Build full signed split APKs in out/ and dist/
npm run patch
```

After pushing dev bundles or installing patched APKs, inspect `adb logcat` for `[Nekocord]` startup diagnostics and confirm zero uncaught `ReactNativeJS` errors.

## Code & Plugin Standards

- **Plugin metadata:** Every new plugin directory must include both `index.ts` and `README.md` with `name`, `description`, `category`, and structured `authors` (`name` + `icon` URL). See [HOW_TO_MAKE_A_PLUGIN.md](HOW_TO_MAKE_A_PLUGIN.md).
- **ES2018 compatibility:** Keep runtime TypeScript compatible with esbuild target `['es2018']` and Hermes (avoid `BigInt` literals, `replaceAll`, `Array.at`, and `Object.hasOwn`).
- **Clean lifecycle & modularity:** Unsubscribe listeners and revert monkey patches in `stop()`. Extract shared helpers in `runtime/src/plugins/_shared/` rather than duplicating logic across plugins.
- **No generated artifact commits:** `registry.generated.ts` and `docs/PLUGINS.md` are regenerated by `npm run gen:plugins` / `npm run typecheck`. Keep `dist/`, `out/`, `apk/`, `apktool/`, and `jadx/` untracked.
- **Strict privacy & safety:** Never add telemetry, analytics beacons, remote script evaluation, or credential exfiltration.

## Submitting a Pull Request

1. Fork `https://github.com/flufstails/nekocord` and create a feature branch:
   ```sh
   git checkout -b feat/my-plugin
   ```
2. Keep commits focused using Conventional Commits (for example `feat(plugins): add MyCustomPlugin`, `fix(ui): align switch thumb animation`, `docs: clarify plugin frontmatter`).
3. Verify that all checks pass cleanly:
   - `npm run typecheck` exits `0`
   - `npm run build:runtime` builds both JS bundles cleanly
   - UI or runtime changes are verified on an Android device or emulator with clean `logcat`
4. Open a pull request describing what changed, why it is needed, and how it was verified.
